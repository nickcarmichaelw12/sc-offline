# asop5: native-compatible entitlement identity

Replaces the sentinel header/discriminator and floating-point payload used by
the original synthetic URNs with communal / entitlement / UUID encoding. Header
bytes are 0x0f, 0x16; identifier kind is 3; UUID payload tag is 2. Payload contains
the existing offline marker/session slot and a separate namespace word. Retrieval
checks the full namespace and bounds before accepting a local slot.

The asop4 call-site validation overrides have been removed. The game now uses
its own validator and equality function. This fixes a concrete defect in our
synthetic identity format; it is not a claim of complete delivery support.

The test tool tools/test_native_urn.py accepts a locally supplied CL12660092
executable on Linux x86-64. It maps the code section privately and invokes only
checked, isolated native URN paths through a Windows ABI adapter. No game files
or dumps are bundled/uploaded. The fixtures are generated by the same header
used by the mod. The tool reproduces legacy validity/equality failure and checks
new validity, self equality, distinct ships, repeated copying and reassignment.
It does not run the game or validate live services/UI.

Native test passed on the supplied executable. CI checks encoding bounds,
compilation and bridge regressions without needing the executable.

Session index bindings remain fixed until restart, as in asop3. They are not yet
persistent server delivery identifiers. No Aurora class mapping changes.

Remaining work: native delivery request adapter and authoritative operation
reservation; real hangar instance readiness and elevator registration; verified
pad transform and ship placement; ATC door lifecycle. Delivery stream failures
remain a separate dependency. Avoid repeated user launch requests until the
offline checks and further adapter work justify a combined in-game checkpoint.
